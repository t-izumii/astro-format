# 基本原則・共通ルール

## 基本原則（優先順位順）

1. **アクセシビリティ** — 最優先
2. **一貫性** — プロジェクト内でコードスタイルを統一（🔴）
3. **可読性** — 他者が読んで理解できるコード（🔴）
4. **保守性** — 変更・拡張が容易な構造（🟡）
5. **パフォーマンス** — 必要最小限のリソース（🟡）

### 一貫性のルール
- 🔴 既存コードに新規コードを追加する場合は、既存のスタイルに合わせる
- 🔴 ガイドラインと既存コードが矛盾する場合は、既存コードの一貫性を壊さない方向を優先

### 可読性のルール
- 🔴 変数名・クラス名は省略しすぎず、意図が伝わる命名にする
- 🔴 「なぜそうしたか（Why）」をコメントで残し、「何をしているか（What）」はコード自体で表現する

### 保守性のルール
- 🟡 コンポーネント単位で独立性を保つ
- 🟡 マジックナンバーを避け、変数・カスタムプロパティで意味を持たせる

## テキストファイル共通ルール

- 🔴 文字コード: UTF-8（BOMなし）
- 🔴 改行コード: LF
- 🔴 インデント: 半角スペース2つ（タブ禁止）
- 🔴 ファイル末尾: 空行1つ
- 🔴 行末の空白: 削除（Markdown除く）
- 🔴 TODO/FIXMEコメントは対応完了後に削除
- 🟡 コメントは日本語
- 🟡 1行120文字以内目安（Prettierの`printWidth`に従う）

## コメントプレフィックス

| プレフィックス | 用途 |
|---|---|
| `TODO:` | 今後対応が必要 |
| `FIXME:` | 既知の不具合 |
| `HACK:` | 一時的な回避策 |
| `NOTE:` | 補足説明 |
