# 名前は役割で付け、見た目や位置で付けない

- 強さ: 推奨
- 対象: 変数、関数、クラス、ファイル、カスタムプロパティなどの名前。

名前は、それが何のためにあるかで付ける。`red-text`、`left-box`、`box2`、`data2` のように、見た目、位置、番号で付けない。真偽値は「〜かどうか」が分かる名前にし、関数は何をするかが分かる動詞で始める。

理由: 見た目や位置の名前は、デザインが変わると実態と合わなくなる（赤くない `red-text`）。番号の名前は、違いが名前から分からない。

例外・代替: 色の一覧などの基礎値のトークンや、見た目そのものを表す補助クラスは、値や見た目で名前を付けてよい。

- 構築: 名前を付ける前に、同じ役割のものに既存の名前がないかを探す。
- レビュー: 見た目・位置・番号の名前と、実態と合わなくなった名前がないかを確認する。
