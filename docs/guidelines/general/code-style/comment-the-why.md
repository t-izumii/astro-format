# コメントには、コードから読み取れない理由を書く

- 強さ: 推奨
- 対象: コメントを書く場合。

コメントには、なぜそう書いたのか、どんな前提に依存しているのかを書く。「ボタンがクリックされたとき」「配列をループする」のように、コードを読めば分かることを言い換えたコメントを書かない。

理由: コードを言い換えたコメントは、読む量を増やすだけで、コードを変えたときに食い違いの原因になる。

例外・代替: 外部から使われる関数や部品の、受け取る値と返す値の説明は書いてよい。

- 構築: コメントを書く前に、名前を変えるだけで意図が伝わらないかを検討する。
- レビュー: コードを言い換えただけのコメントがないかを確認する。
