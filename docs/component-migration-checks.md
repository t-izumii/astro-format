## ルーティング専用化の再確認

ユーザー指定に合わせ、ページ実装を `src/components/pages/top/` / `about/` へ移動し、SCSS は部品側で集約した。`src/pages/` は `index.astro` と `about.astro` のみ。型チェック・各 Lint・ビルド・差分検査を再実行して合格。出力の2ルートとページ CSS の収録、開発カタログ CSS の除外を確認した。上記のブラウザ操作記録はこの配置変更前のものであり、今回の再確認は生成物まで。

## JavaScript 接続の data 属性への移行

初期化セレクタ・モーダルの閉じる操作・UI の出力・利用例を data 属性に統一。設定属性を接続にも利用し、未使用のコンテナ用フックを削除。マーキー内部の内容検索も data 属性へ変更した。

- 型チェック・JS / HTML Lint・ビルド・差分検査に合格。追加したカタログの属性とリンクも HTML Lint に合格。
- ソースとカタログ DOM に旧フックが残っていないことを確認。
- サイズ監視による CSS 変数の更新、画面内判定による状態付与、指定位置へのスクロールを確認。
- 3つのカルーセルと5つのマーキーの初期化を確認。次へ操作によるスライド移動と、画面内のマーキーの変位更新を確認。
- 開発カタログと本番でモーダルの開閉とフォーカス復帰を確認。開発カタログの確認時にブラウザエラーなし。

状態クラスと外部ライブラリの必須クラスは各用途を維持。CSS クラスを受け取る部品 API 自体は今回変更していない。

## クラス受け渡しと CSS 変数の整理

全9部品のクラス結合を撤去し、props 型から class / className を除外。内部クラスを固定した。公開変数は用途だけの名前、内部変数はアンダースコア付きとし、部品ルートで `--_size: var(--size, 1em)` の形に解決する。利用箇所・カタログ・README・制作ルールも更新。

- 型チェック・JS / CSS / HTML Lint・本番ビルドに合格。
- カタログのボタンは固定クラスのみ。公開変数の指定で padding が12px 32px、背景が #222、文字色が白になることを確認。
- Container の最大幅720px・余白16px、Grid の PC 3列 / SP 1列・行間12px を確認。
- Icon の既定16px、指定24px・64px、PC 40px / SP 24px、Button 内の Icon 16px を確認。内部変数の解決値も確認。
- SP 幅390px で横はみ出しなし。モーダルの既定幅326px・高さ780px、開閉・フォーカス復帰を確認。カタログのブラウザエラーなし。

公開変数は子孫へ継承する。異なる部品で同名を使う場合の継承と、initial による解除方法は README に明記。今回のブラウザ検証はカタログで行い、本番出力はビルドまで確認した。

## 全コンポーネントの Props 明示化

Button に続き、残り8つの共通部品・Layout・MarqueeDemo の props を継承なしの interface に統一した。children、style、必要な標準属性・ARIA 属性・data 属性・固有の動作設定を各ファイルに明記。入力のない部品に空の Props は追加していない。受け取る属性を追加する際のルールを README と CLAUDE.md に反映した。

TypeScript・HTML Lint・ビルド・差分検査に合格。型定義変更前後の dist 全ファイルを SHA-256 で比較し、内容の差分がないことを確認。今回は型と文書の変更として検証し、ブラウザでの操作は再実施していない。現在の ESLint 設定は TSX を対象にしていないため、TSX の確認には TypeScript と markuplint を使用した。

## 標準属性の継承と rest への整理

最新の指定に合わせ、全9共通部品で HTML 属性型を継承し、children と固有入力だけを明記する形へ統一。標準属性は rest で渡し、内部クラスは固定。class / className の型による禁止は行わず、追加クラスを渡さない運用とする。以前の個別列挙ルールは README / CLAUDE.md で更新した。

型チェック・HTML Lint・ビルド・差分検査に合格。変更前後の本番出力を SHA-256 で比較し、全ファイル一致。型と文書の変更のためブラウザ操作は再実施していない。

## 非推奨の属性型参照の修正

全9共通部品の属性型を、JSX 名前空間経由から preact の直接 import に変更。README の例と CLAUDE.md の制作ルールも更新した。TypeScript のシンボル解決で、参照先の4種類の属性型に deprecated タグがないことを確認。

型チェック・HTML Lint・ビルド・差分検査に合格。変更前の本番出力7ファイルと SHA-256 が一致。型参照の変更のためブラウザ操作は再実施していない。

## Layout 部品のディレクトリ化

依頼に合わせ Header / Footer を各ディレクトリの index.tsx へ移動し、index.scss と集約用 \_index.scss を追加。既存 import はディレクトリの index に解決される。仮スタイルは固定の l-header / l-footer に限定し、余白を `--_padding: var(--padding, 0)` で解決する。

適用基準は CLAUDE.md の関連ファイルの隣接配置と変数規約、基盤 rules/components.md「契約変更後もサポートする利用を成立させる」、rules/css-design.md「意図した対象と状態に適用する」、rules/code-quality.md「名前から役割と値の意味を読めるようにする」。利用側の import と CSS 集約をビルドで確認し、型チェック・CSS / HTML Lint・差分検査に合格。開発トップページの DOM と算出スタイルで両クラス、内部変数0、padding 0px を確認した。新規操作はなく、画面操作の再検証は行っていない。

## Icon の個別色指定

公開変数 --color を追加し、内部 --\_color を経由して color に適用。SVG の currentColor が各インスタンスの色を参照する。SVG ルートへの一括 fill / stroke 指定は撤去し、元の fill="none" と各パスの描画指定を保持した。README に新規 SVG の currentColor 規約を記載。

CLAUDE.md の公開変数規約と、基盤 rules/css-design.md「意図した対象と状態に適用する」、rules/components.md「利用条件の範囲で独立して動作する」を適用。開発カタログに同じ SVG の赤・青・緑の3例を追加し、各パスの算出 stroke が指定色に一致し fill は none のままであること、未指定時に親の文字色を継承することをブラウザで確認。型チェック・CSS / HTML Lint・ビルドに合格。
